## Источник правды

## Технологии

## Принятые решения
1. (2026-10-07) Все три пункта раздела 6 ТЗ подтверждены: выбранная папка запоминается между запусками, одновременно идут 2–3 загрузки, в меню есть «Обновить загрузчик».
2. Проект лежит в отдельной папке `Desktop\TikTok Downloader` со своим git-репозиторием.
3. Python пользователь поставил сам с python.org — версия 3.13.12 (вместо 3.12, подходит).
5. (2026-10-08, изменение ТЗ по просьбе пользователя — раздел 4 «другие платформы» снят) Добавляются YouTube (обычные и Shorts), Instagram, X (Twitter). ffmpeg и Deno (для YouTube) встраиваются в .exe. Качество YouTube: Максимальное · 2160p · 1440p · 1080p (по умолчанию) · 720p · 480p · 360p, при отсутствии — ближайшее меньшее, всегда mp4; выбор в окне рядом с папкой, запоминается. Программа переименована в «Video Downloader», папка по умолчанию `Загрузки\Video Downloader` (внутренние имена — реестр TikTokDownloader и `%LOCALAPPDATA%\TikTokDownloader` — не меняем, чтобы не потерять настройки и cookies). Рядом с .exe — файл лицензии ffmpeg. Файлы — в подпапках по площадкам (TikTok\, YouTube\, Instagram\, X\) выбранной папки, имя `автор_id.mp4`. Вход — отдельный cookies.txt для каждой площадки (вход из браузера и окно входа — не делаем).
6. (2026-10-08, по просьбе пользователя) Ожидаемый размер видео: сразу после «Добавить» программа в фоне получает данные (автор, обложка, размер), статус «Можно скачивать · ≈ N МБ», внизу итог по списку; при смене качества YouTube размеры пересчитываются без сети; во время скачивания «12,3 из 45,6 МБ». Размер: точный, если площадка его даёт (YouTube, TikTok), иначе ≈ битрейт × длительность (X), у Instagram — запрос размера файла у сервера. Делается до сборки .exe (шаг 11а).
4. (2026-10-07, сверх ТЗ по просьбе пользователя) Видео 18+ («Log in for access») — через файл cookies.txt: пользователь сохраняет его расширением «Get cookies.txt LOCALLY» и указывает в меню «Загрузчик». Варианты «cookies из браузера» и «окно входа в программе» отклонены (Chrome/Edge шифруют cookies; +150 МБ к .exe).

## Окружение
- Python: `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`.
- Окружение проекта `.venv` (в git не хранится); версии библиотек — `requirements.txt`. Запуск: `.venv\Scripts\python.exe`.

## План
1. Поиск ссылок TikTok в тексте (+ короткие vm/vt, без дублей) и проверки.
2. Загрузчик одного видео: без водяного знака, имя `автор_id.mp4`, «уже скачано», прогресс.
3. Главное окно: поле ссылок, «Добавить», выбор папки (запоминается, по умолчанию Загрузки\TikTok), список.
4. Очередь: 2–3 загрузки параллельно, «Скачать всё», «Остановить», «Очистить список», «Повторить», «Открыть папку», обложки.
5. «Обновить загрузчик» в меню (способ для .exe решить на этом шаге).
6. Сборка одного .exe через PyInstaller и проверка на чистом запуске.

## План 2 (несколько площадок, согласован 2026-10-08)
7. Ссылки YouTube/Instagram/X, определение площадки, подпапки, переименование → 8. X → 9. Instagram → 10. «Аккаунты»: cookies на площадку (перенос TikTok) → 11. YouTube: ffmpeg + Deno, выбор качества → 12. Сборка, размер, скорость запуска.

- Шаг 2: `app/downloader.py` — download(url, folder, on_info, on_progress, should_stop) → Result(status, path, message); статусы fetching/downloading/done/already/error/stopped. Формат: без «watermarked»/«UNPLAYABLE», с видео и звуком, предпочтение h264, потом высота и битрейт. Имя `автор_id.mp4` (автор = uploader, запрещённые знаки → _). Остановка — исключение из progress hook, недокачанное (.part) удаляется. explain() — короткие причины на русском. Ручная проверка: `tools/try_download.py <ссылка> [папка]`. 18 проверок OK.

Меню «Загрузчик»: «Обновить загрузчик» (в фоне, потом предложение перезапуска) и «Версия yt-dlp: …». Версии сравниваются как числа (2026.8.19 = 2026.08.19). - Шаг 8 (X): downloader переписан под площадки. fetch_info — `extract_info(process=False)` (иначе yt-dlp сам выбирает формат, и при скачивании другого берёт ссылки своего выбора — у X это было 404). Формат выбирает функция `_format_selector` (параметр yt-dlp `format` принимает функцию): pick_format(formats, platform) — у TikTok без «watermark», везде без «unplayable», без явного «none» у vcodec/acodec (None = неизвестно, у X так подписаны цельные mp4), цельный файл раньше m3u8, потом h264, высота, битрейт; если цельного нет — склейка `bv*+ba/b` (нужен ffmpeg), у TikTok — ошибка. Пост с несколькими видео — `playlist_items=N`, файлы `автор_id_N.mp4`, уже скачанные пропускаются, статус «видео N из M» (on_part). Автор X — uploader_id (ник), id — номер поста из ссылки. Ошибки X переведены. Проверено без ffmpeg в PATH: одно видео 728×720, пост с 4 видео, «уже скачано», докачка недостающего, остановка без мусора. 42 проверки OK. Тестовые посты: `x.com/historyinmemes/status/1790637656616943991` (1 видео), `x.com/UltimaShadowX/status/1577719286659006464` (4 видео). Подтверждён.
- Шаг 9 (Instagram): без входа yt-dlp отдаёт открытые Reels/посты. Форматы: 3 цельных mp4 без описания (format_id/размер пустые, лучший — первый; у CDUMkliABpa он 720×1280 = максимум DASH) + DASH раздельно. pick_format берёт первый цельный. Ошибки Instagram переведены (закрытый аккаунт, лимит без входа, Restricted Video, пустой ответ). Подтверждён.
- Шаг 10 («Аккаунты»): `app/cookies.py` — файл на площадку `%LOCALAPPDATA%\TikTokDownloader\cookies\<площадка>.txt`; старый `cookies.txt` сам переносится в `cookies\TikTok.txt` (перенёсся у пользователя). Проверка входа: TikTok/Instagram — sessionid, X — auth_token (x.com/twitter.com), YouTube — LOGIN_INFO/SAPISID/__Secure-3PAPISID/__Secure-1PSID (youtube.com/google.com). downloader._ydl(extra, platform) грузит только cookies этой площадки. explain(error, platform): `_LOGIN_RULES` — ошибки «нужен вход», к ним подсказка «меню «Аккаунты»» или «вход не подошёл — сохраните заново». Меню «Аккаунты»: подменю площадок «X — вход указан ✓ / без входа» (Указать файл cookies…, Удалить вход) и «Как сохранить файл cookies?». Из «Загрузчика» пункты cookies убраны.
- **Исправлено попутно (ошибка с шага 8):** с `process=False` короткие ссылки (vm/vt.tiktok.com) приходят как `_type: url` → автор и id пустые, файл `unknown_unknown.mp4`. `_resolve()` проходит переадресации (url и url_transparent). Проверено на реальных vt.tiktok.com (обычное и 18+ с cookies пользователя). 48 проверок OK. Подтверждён.
- Шаг 11 (YouTube): нужны `yt-dlp-ejs` (скрипты разбора защиты; ставится как `yt-dlp[default]`), Deno и ffmpeg. `tools/get_vendor.py` качает в `vendor/bin` (в .gitignore) ffmpeg.exe из github.com/yt-dlp/FFmpeg-Builds (latest win64 gpl, сумма из checksums.sha256; ffprobe НЕ берём — для склейки не нужен, 160 МБ) и deno.exe из github.com/denoland/deno (сумма из .sha256sum в формате PowerShell «Hash : …»), лицензии — в `vendor/licenses`. Размеры: ffmpeg 161 МБ, Deno 93 МБ (2.9.7; yt-dlp требует ≥ 2.3). `app/vendor.py` — путь (в .exe — sys._MEIPASS/vendor/bin), параметры yt-dlp `ffmpeg_location` и `js_runtimes={'deno': {'path': …}}` в _BASE_OPTIONS. Для YouTube `noplaylist`. Выбор качества — `youtube_pick(formats, quality)`: наибольшая высота ≤ quality (иначе наименьшая), до 1080 на ней h264, без m3u8, звук — AAC; дальше `build_format_selector("видео+звук")`. **Важно:** у вспомогательного экземпляра yt-dlp в _format_selector должен быть `merge_output_format: mp4`, иначе VP9/AV1 склеиваются в .mkv. Автор YouTube — uploader_id без «@». Окно: «Качество YouTube» (QComboBox рядом с папкой, settings.load/save_quality), качество едет через очередь. Проверено без системного ffmpeg: `youtube.com/watch?v=2NUZ8W2llS4` 1080 → h264 1920×1080, 2160 и «макс» → VP9 3840×2160 mp4, 360 → 640×360; Shorts-ссылка; `jNQXAC9IVRw` (только 240p) при 360 → 240p; «уже скачано»; остановка без мусора. Тестовый ролик yt-dlp BaW_jenozKc недоступен. 56 проверок OK. Пользователь не проверял отдельно — сразу попросил размеры (решение 6).
- Шаг 11а (размеры, решение 6): `app/sizes.py` (human, estimate_text: «45,6 МБ», «≈ …», «размер неизвестен»). downloader: fetch_info = извлечение + `summarize(url, info)`; `estimate_size(url, info, quality, ask_server)` / `_entry_size` — формат выбирается как при скачивании; размер: filesize (точно) → filesize_approx (≈) → HEAD-запрос Content-Length (если ask_server; X и Instagram) → tbr × длительность (≈; у X битрейт — «потолок», завышает в 3 раза, поэтому после HEAD). `download(..., prefetched=info)` — данные проверки, если свежее INFO_FRESH_SECONDS (15 мин). Прогресс: общий по картинке и звуку YouTube, итог — из `_entry_size` без сети. download_queue: `probe()` — отдельный пул PREFETCH_PARALLEL=2, сигналы probed/probe_failed. ItemWidget: статусы PROBING «Получение данных…», READY «Можно скачивать», size_label справа от автора, info/info_time, «Скачивается · 12,3 из 45,6 МБ». Окно: при «Добавить» — probe; итог справа в строке состояния «Видео: N · X МБ (без размера: K)» без готовых и ошибок; смена качества пересчитывает YouTube без сети. **Исправлено попутно:** немые ролики (звука нет ни в одном формате; поток «только звук» — vcodec none — считается звуком) — pick_format берёт картинку (раньше уходило в склейку, размер не считался). Сверка оценки с реальным размером: YouTube 1080/360, TikTok, X (по HEAD), Instagram Reel и карусель — расхождение < 1%. 66 проверок OK. Ждём подтверждения.
- **Для сборки .exe:** `--copy-metadata yt-dlp` (иначе bundled_version() = 0 и любой .whl будет считаться новее), собрать curl_cffi целиком.
- **Важно:** без curl_cffi TikTok отдаёт yt-dlp страницу-проверку («Unexpected response from webpage request») — ставить `yt-dlp[curl-cffi]`, при сборке .exe не потерять curl_cffi.
- Тестовое видео: `https://www.tiktok.com/@hankgreen1/video/7047596209028074758` (скачивается); `@leenabhushan/video/6748451240264420610` — «IP заблокирован» (проверка ошибки региона).
